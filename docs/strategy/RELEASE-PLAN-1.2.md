# Release plan: PHP Ledger 1.2

Drafted 20 September 2026 (evening) from the code on `master` at `9a25d63`, the published releases, the open GitHub issues and the owner decisions B18–B26. **Status: proposal for the owner. Nothing in it is built, tagged, published or deployed.** Every date is an estimate; every "owner decides" line is open until it carries a date in the [decision register](DECISION-REGISTER.md).

1.2 is the next major release on the [roadmap](../ROADMAP.md#following-stable): the seven items the owner sequenced on 19 September 2026 (B20, B21), delivered in that order. This plan says where each item stands in the code today, what remains, how the work is cut into previews and one stable release, what has to be true before 1.2.0 publishes, and which questions only the owner can answer.

## The short version

- **Only item (a), stock locations, is code today, and it is already inside the published 1.1.1 package without being announced.** The v1.1.1 tag carries migration `034_inventory_locations` and the `inventory-locations` module while the 1.1.1 release notes, `UPGRADE.md`, README, wiki and website all say "no schema change, no migration". A 1.1.0 operator who follows those notes and replaces files leaves 034 unapplied. This is the first thing 1.2 planning has to repair.
- **Items (b) to (g) do not exist in code.** No trading-document columns, no number series, no unapplied credit, no hooks API or plugins folder, no capability tables, no translation helper or catalogue, no production container image. Roughly 53 to 88 engineering days remain, including a small 1.1.2 patch and the release walks.
- **Shape:** a 1.1.2 patch this week so pilot #1 starts on 1 October on a release whose public record is true and whose in-app upgrade path works; then three signed previews on the preview channel after natural pairs of items; then 1.2.0 stable with the container image, the reviewed Urdu and a major-release media kit.
- **Target for 1.2.0: Friday 15 January 2027** (earliest Friday 8 January 2027, latest Friday 12 February 2027). Nothing publishes in the week of 21 December. The pilot stays on 1.1.2 through the October, November and December closes and cuts over to 1.2.0 as a dated, backed-up event after the accountant's decision.
- **Fifteen owner decisions** are dated below; the first four are needed by 25 September.

## Shape: one patch, three previews, one stable

The [release protocol](../RELEASE-PROTOCOL.md) is walked for every publication. Previews go on the preview channel, never move `latest` or the stable feed entry, and carry no media kit (owner decision 3 below extends the 20 September waiver to previews). Each preview installs migrations that cannot be reverted, so previews are for testers on disposable copies (B25); the pilot never runs one.

**How a tester reaches a preview.** The feed reader derives an installation's channel from its own version (`pl_release_channel_for()`), so the feed offers the preview channel only to installations already on a preview version. A stable installation reaches a preview by choosing "Preview" on the maintenance page and uploading or downloading that preview's signed metadata; from then on the feed offers later previews. A preview installation returns to stable by choosing the stable channel when 1.2.0 exists. The tester note on each preview says this in those words.
