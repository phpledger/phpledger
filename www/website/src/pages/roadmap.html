The path from a first stable release to independently reviewed books

The published package has a bounded accounting starter spanning customer and supplier documents, payments and optional stock workflows, plus browser installation and signed updates. Independent review, pilots and the release-candidate acceptance period continue after publication as disclosed post-release commitments.

In short

  • PHP Ledger {{site.release.version}} is the current stable release, with core AR/AP, optional Purchasing and Inventory, manual tax, reports, scoped read connections, browser installation from any web folder on MySQL 8.4 or MariaDB 10.4+, and signed automatic updates.
  • Invoices, bills, partial payments, linked credits, ageing and reconciliation now use the shared party, open-item and correction foundations.
  • Since 1.1.0: 1.1.1 shipped six-stage browser setup, local-database and plain-HTTP handling, a trigger preflight with resumable migrations, one database account, corrected demo labels and, unannounced, migration 034 with the optional Stock locations module; 1.1.2 corrects that record, holds POS cash to whole minor units and restores signed update metadata. The demo packs stay in the package until 1.2.
  • The next releases, in order: 1.2 (stock locations documented, trading documents, on-account receipts, the plugin runtime, user capabilities, Urdu and a container image) and 1.3 (Arabic, table prefix, installation notice, cloud databases and more channels).
  • Advanced inventory, statutory tax adapters, reviewed statement packages, independent accounting/security review and supervised pilots each need separate delivery and acceptance evidence, disclosed as open post-release commitments rather than completed gates.

This roadmap describes development scope, not a delivery-date or regulatory-compliance promise.

Development sequence

  1. Available

    1.1.1 and 1.1.2: setup you can watch, and the record corrected

    1.1.1, published 20 September 2026, rebuilt browser setup into six stages you can follow, with a progress bar during the build. It accepts a local database account with no password and creates the database itself, warns instead of refusing over plain HTTP, reads the MySQL binary-log trigger setting at the connection check and resumes an interrupted migration from its first unapplied statement, asks for one database account instead of two, and ships the corrected demo labels. It also carried, unannounced, migration 034 and the optional Stock locations module, off by default.

    1.1.2, published 20 September 2026, corrects that record, holds cash at the point of sale to whole minor units and restores signed update metadata, so an installation on 1.1.0 or 1.1.1 with the publisher key pinned installs it from /maintenance.php. The demo packs did not leave the package; that work moves to 1.2. Read the 1.1.2 release notes and the 1.1.1 notes.

Frequently asked questions

Is there a stable release?

Yes. PHP Ledger 1.1.2, published 20 September 2026, is the current stable release. It follows 1.0.0, the first stable release of 18 September 2026; 1.1.0 (19 September) added installation from any web folder, MariaDB support, a chosen username, an optional logo and signed update metadata, and 1.1.1 (20 September) rebuilt browser setup into six stages you can watch. 1.1.2 corrects the 1.1.1 record, holds cash at the point of sale to whole minor units and restores signed update metadata. Independent accounting review, independent security review and supervised pilots have not yet happened; they continue as post-release commitments, disclosed alongside the release rather than presented as satisfied. The first supervised pilot, on the maintainer's own books, starts 1 October 2026 with a real month-end close.

Does choosing a country or currency activate local accounting rules?

No. Each book uses one base currency. Country and currency choices do not activate tax calculations, statutory reporting, foreign-currency posting or additional accounting books. The core is country-neutral. Pakistan FBR is one planned connector; each regional accounting or tax integration needs separate research, implementation and review.

How can I help shape the next release?

Share a fictional workflow example, installation report or reproducible issue through the project repository. Accountants, business owners and contributors can also use the enquiry form on the pricing page to prepare a message about review or pilot participation.

Which parts are ready to evaluate?

Use the release boundary to choose a test task; a schema foundation does not mean the operator workflow is available.
