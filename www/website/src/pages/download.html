Install from the browser

Six steps from upload to sign-in, with no terminal on your side and no need to change the document root. The installer explains each check it makes and stops with a clear message if the host is missing something.

  1. Unzip and upload

    Unzip the package. It creates one folder named phpledger. Upload that folder anywhere inside your website, such as the domain root, public_html/accounts or XAMPP's htdocs.

  2. Create an empty database

    In your hosting panel, create an empty MySQL 8.4 or MariaDB 10.4+ database and a dedicated user with all privileges on it. Never use an existing business database or the root account.

  3. Open the folder's address

    Open the folder's address in your browser. The installer starts by itself and checks the PHP version, extensions and that private files cannot be downloaded.

  4. Connect and migrate

    Enter the database details. With the database on the same server (localhost) no setup key is needed. The installer runs the migrations and records the schema version it installed.

  5. First account and business

    Choose a username, email address and password for the first account, add a logo if you want one, then set up your business: name, base currency, country package and financial year.

  6. Sign in

    Sign in with your username or email and start with your chart of accounts, tax codes and opening balances, or open a sample company to practise first.

Updates and recovery

Updates arrive as signed releases, applied from /maintenance.php. Before every update the application takes an automatic backup that matches the release, so the books on disk and the schema being upgraded always agree, and the signature is verified before a single file is unpacked.

If a migration fails part-way, recovery runs automatically and the application returns to the previous working release. Hosts that need it can also use a CLI companion for recovery outside the browser.

Upgrading an existing installation

1.1.0 was the first release with signed update metadata; 1.1.1 was published without it, and 1.1.2 and 1.1.3 carry it again. An installation on 1.1.2 installs 1.1.3 from /maintenance.php once the publisher key is pinned, and that path was driven end to end before publication. An installation on 1.1.0, or any installation more than one release behind, upgrades by replacing the files and running php www/phpledger/install/migrate.php once (issue #91). The key’s SHA-256 fingerprint (DER SubjectPublicKeyInfo) is 4e58a5f46b0538c9b37aaadbfced9a2d8ad2f7d413bc168a67b1b94feaa78e78; check it against the release signing guide before pinning.

Take a backup first and never unzip a new version over an installed copy; the staged path is deliberate, because older databases can differ from the {{site.release.version}} schema in more than one place.

Questions before you install

Can I use it for real books today?

Yes, with the published limits in mind. Version 1.1.3 is the current stable release, and the accounting core covers invoices, bills, stock, bank reconciliation and the standard reports. Independent accounting and security reviews, and supervised pilots, are still open commitments on the roadmap. Keep backups, and read the roadmap before you commit a live business to it.

How do I verify the download?

Each release page publishes a .sha256 file next to the ZIP. Compute the SHA-256 checksum of the ZIP you downloaded and compare it with the file before you unpack anything. If the checksums differ, do not install it; download the package again.

Does shared hosting work?

Yes. PHP Ledger is built for ordinary shared hosting: PHP 8.2 or later with the required extensions, a MySQL 8.4 or MariaDB 10.4+ database, and HTTPS. Upload the phpledger folder into your website and open its address; the installer runs in the browser, with no terminal, Composer, Node or Docker needed for setup. Uploading into any folder relies on .htaccess, so it needs Apache or LiteSpeed, which most shared hosts use.

Does it work with MariaDB?

Yes. Since version 1.1.0, MariaDB 10.4 or newer is supported alongside MySQL 8.4, both with InnoDB. The full test battery of 294 tests passed on MariaDB 10.4, 10.6, 10.11 and 11.4 and on MySQL 8.4. MySQL 8.0 is not supported yet.

Do I need a setup key?

Not for a normal install. When the database is on the same server (localhost), the installer opens without a key. A database on another server needs a one-time code that the installer writes to private storage; read it with your hosting file manager. An operator who wants a key for every installation can still require one.

Which licence applies?

New project-owned code uses AGPL-3.0-or-later; a commercial licence is available on request. Dependencies, fonts, photographs and the archived 2015 application keep their own terms.

Where is the source?

The full source is on GitHub at github.com/phpledger/phpledger. The release tag v1.1.3 holds the package, the checksum file and the release notes, and the repository carries the development history.

Automated test suites, fault-injection tests of the update and recovery path, exact-artifact installation, upgrade and recovery checks all passed. Independent accounting review, independent security review, supervised pilots with a real month-end close and a release-candidate period have not been performed yet, and the 1.1.3 installer has not yet been observed on a real shared host or with an unfamiliar operator; these are open post-release commitments listed on the roadmap.
